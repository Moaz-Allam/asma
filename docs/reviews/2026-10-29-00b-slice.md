## Major
- D:\work\web\asma\next.config.ts:52-56 and :81 - Cookies go to PostHog and Sentry through the same-origin paths.
  - **Problem:** `/api/a/*` and the SDK's `/api/e` tunnel are external rewrites, and Next forwards every incoming request header to the destination (`node_modules\next\dist\server\lib\router-utils\proxy-request.js`, httpxy, no header filter).
  - Neither SDK sets a `credentials` mode: posthog-js has none, and Sentry's fetch transport (`node_modules\@sentry\browser\build\npm\cjs\prod\transports\fetch.js:17-30`) has none. So every first-party cookie reaches `eu.i.posthog.com` and `o<org>.ingest.de.sentry.io`.
  - Today that is `NEXT_LOCALE`, plus possibly `_vercel_jwt` on protected previews.
  - From 01, the `@supabase/ssr` session cookies (access JWT with email and phone claims, refresh token, user object) would ride along with every event, outside the scrubber (AC-3, AC-6).
  - The e2e stubs both paths in the browser, so nothing tests what goes upstream.
  - **Fix:** serve `/api/a/*` and `/api/e` from Route Handlers that forward an allow list of headers (content-type, content-encoding, user-agent) to fixed EU destinations. Add a test that the upstream request has no `cookie`. Do this before 01.
- D:\work\web\asma\lib\observability\scrub.ts:201-203 - URLs inside message text keep their sensitive parameters and fragments.
  - **Problem:** `redactMessage` only redacts emails, IPs and phones; it never calls `scrubUrlsInText`.
  - It is used for exception values (:350), `event.message` (:373), `logentry.message` (:378), log messages (:420) and breadcrumb messages (:330).
  - Concrete failure: Sentry's console breadcrumb stores the joined arguments in `message`. `console.log('callback', 'https://x/auth/confirm?token_hash=abc#access_token=…')` gets its `data.arguments` copy scrubbed, but `message` ships the token.
  - AC-3 requires sensitive parameters and every fragment stripped, so it is only partly met.
  - **Fix:** run `scrubUrlsInText` inside `redactMessage`. Add tests for a token URL in an exception value and in a console breadcrumb message.
- D:\work\web\asma\lib\observability\alert.ts:39 - Production "new alert issue" emails will not fire for records that alerted elsewhere first.
